# 残光 ZANKO（仮題）

ダッシュ・壁蹴り・セイバーの連撃を軸にした、2D横スクロールアクションの操作プロトタイプ。
Canvas 2D、ライブラリなし、ビルドなし。画像ファイルは使わず、キャラクターも背景もコードで描いている（後でスプライトに差し替える前提の仮の絵）。

- 現在の版: **v0.5.1**（空気感、シェーダー効果、色調整、作り直した効果音とBGMを足した版。操作とルールは v0.1.0 と同じ）
  - v0.3.0 で、主人公、敵、設備、壁と床、隔壁、トゲ、遠景を絵に差し替えた。ポーズメニューの「絵の表示」で、すべてコード描画に戻せる
  - v0.4.0 で、遠景の霧と霞、光だまり、空気中の塵、手前の配管、色調整、ビネット、粒状感、ブルーム、床の映りこみを足した。ポーズメニューの「空気感」でまとめて切れる
  - v0.4.0 の空気感はすべて 2D の canvas の重ね描き。調整用の値は `js/render.js` の `TUNE`（セイバーの明るさ）、`HERO_REFLECT` と `SABER_REFLECT`（映りこみの濃さ）にまとめてある
  - v0.4.4 で、シェーダー効果を足した。2D の canvas の上に WebGL の canvas を重ね、効果が出ている間だけ動かす（ヒット・撃破・タメ完了・やられた時の衝撃波の歪み、タメ完了中の熱のゆらぎ、ダッシュ中の放射状のブレ、被弾時の色ずれ）。ポーズメニューの「シェーダー効果」で切れる。WebGL が使えない環境では自動で無効になる
  - シェーダー効果の調整用の値は `js/render.js` の `POSTFX`（ブレと色ずれの強さ）、`HEAT`（熱の強さ。トゲの上の熱は 0 で切ってある）、`R.event` の中の `R.waves.push`（衝撃波の大きさと強さ）
  - 剣閃と刃のぼかした光（`shadowBlur`）には、ぴったりの切り抜き枠（clip）をつけてある。外すと空中攻撃が重くなる
  - v0.4.5 で、色調整（LUT とトーンカーブ）を足した。これだけは毎コマ動く。ポーズメニューの「色調整」で切れる。LUT は `assets/lut.png`（256×16 の帯）で、`tools/lut.py` が作る。手で作る場合は、色調整を切ったスクリーンショットに掛けた調整を、そのまま `tools/lut_neutral.png` に掛けて `assets/lut.png` に書き出す。強さは `POSTFX` の `lut`、`tone`、`exposure`
  - トーンカーブは、白飛びを戻せない（2D の絵は加算の時点で 255 で頭打ちになっている）。できるのはコントラストの付け直しまで
  - v0.5.0 で、効果音25種を作り直し、BGM（オリジナル曲、32小節のループ）を足した。すべて Web Audio の合成で、音声ファイルは無い（`js/audio.js`）。ポーズメニューに BGM と効果音の音量つまみがある。初期の大きさは `LEVEL`、`node test/audio.js` で音量を測れる
  - v0.5.1 で、ポーズメニューに「描画の解像度」（高・標準・軽量）を足した。canvas の画素数の上限を変える（`js/main.js` の `QUAL`）。タッチ端末の初期値は「標準」（約100万画素）。タッチ端末では、プレイ中に 48fps 未満が3秒続くと自動で1段下げる。ボタンに今の canvas の大きさと直前の fps が出る
- 絵は `assets/` にある。どれも `tools/` の道具が生成したもので、手で編集しない
  - 主人公: `hero.png`（39コマ）と `js/hero_atlas.js`（`tools/atlas.py`）
  - 敵4種: `foes.png` と `js/foe_atlas.js`（`tools/foes.py`）
  - 設備（端末、制御盤、回復カプセル、チェックポイント、ゴールの門）: `props.png` と `js/prop_atlas.js`（`tools/props.py`）
  - 壁と床のパネル `tile.png`、隔壁 `gate.png`、トゲ `spikes.png`、遠景 `bg_far.png` `bg_near.png`（`tools/terrain.py`）
  - 道具の入力（元のシート画像）は、このリポジトリには入っていない。記録として置いてあり、そのままでは動かない
- 絵が読みこめないものは、その種類だけコード描画になる
- 刃、剣閃、火花、発光、案内の文字、空のグラデーションは、コードで描いている
- 刃は、握りの位置に発光を重ね、振りの後ろへ広がる扇形の残像を付けて、絵の柄と刃の向きの食い違いを隠している
- 空中斬りは、地上の三段目の絵を流用している。エアダッシュは専用の絵

## 操作

| | キーボード・マウス | タッチ | コントローラ（DualShock 4 の表記） |
|---|---|---|---|
| 移動 | A / D、← / → | 画面左をドラッグ | 十字キー、左スティック |
| ジャンプ（長押しで高く） | マウス右、Space、K、X | JUMP | × |
| 斬る | マウス左、J、Z | 斬 | □ |
| ダッシュ | 方向キー2度押し、L、C、Shift | DASH | ○、R1、R2 |
| エアダッシュ（試験） | 空中でマウス右、または空中でダッシュ | 空中で DASH | 空中でダッシュ |
| 調べる・動かす | E（W、F、↑ でも） | 物の上に出る札をタップ | △、十字キー上 |
| メニュー | Esc、P | 右上のボタン | OPTIONS |

PC のおすすめは「A / D ＋ マウス」。左手は移動とダッシュ、右手のマウスで斬る（左）とジャンプ（右）。

### 動きの決まり

- **斬る**: 続けて押すと三段斬り。空中、ダッシュ中、壁ずり中はそれぞれ別の斬り。長押しして離すと溜め斬り。斬撃は敵の弾を消せる。
- **ダッシュジャンプ**: ダッシュ中（終わってから 14/60 秒以内も可）にジャンプすると、ダッシュの速度のまま跳ぶ。
- **壁**: 空中で壁に触れてジャンプすると壁蹴り。壁に向かって入力し続けると、ずり落ちる。ダッシュジャンプの速度で壁に着くと、壁蹴りもその速度のまま続く（補助。メニューで切れる）。
- **連続ダッシュ**: 次のどちらかの間、ダッシュが終わるたびに次のダッシュが出て、ダッシュジャンプの着地でもそのままダッシュになる。
  - キーボード: 2度押しした方向を押し続けている間（離すか、逆を押すと解ける）
  - タッチ: DASH を押し続けている間（1回だけ押すと、1回分を最後まで走って止まる）
  - この間に地上で斬ると、ダッシュ斬りになる。
- **エアダッシュ（試験）**: 水平に 18/60 秒（約4タイル）進み、その間は落ちない。1回の滞空につき1回で、着地か壁蹴りで回復。終わった後はダッシュの速度が残る。メニューで切れる。
  - マウス右は状況で決まる: 地上はジャンプ、空中はエアダッシュ、壁に触れていれば壁蹴り、エアダッシュを使った後と着地寸前はジャンプの先行入力。
  - 着地寸前に押したダッシュは、エアダッシュではなく着地でのダッシュになる。
- **調べる・動かす**: 地上で対象のそばにいると、頭上に札が出る。押すと足が止まって手を伸ばし、約0.13秒後に効果が出る（全体で約0.27秒）。被弾すると中断する。
  - 記録端末: 文章のパネルが開き、その間ゲームは止まる。斬る・ジャンプ・調べるのキー、クリック、タップ、コントローラの ×○□△ で送る。
  - 制御盤: 隔壁が開く（1回だけ）。
  - 回復カプセル: 体力が全回復（1回だけ）。
- **確認用**: `F3` 数値の表示（URL に `#debug` でも可）、`H` 当たり判定の表示。

## 構成

| パス | 内容 |
|---|---|
| `js/sim.js` | ルール（移動、斬撃、敵、ステージ、調べる対象）。DOM も canvas も触らない。手触りの数値は冒頭の `C` と `ATK` |
| `js/render.js` | 描画（キャラクターの姿勢、斬撃の軌跡、粒、背景、対象） |
| `js/main.js` | 画面の割り付け、入力（キー、マウス、タッチ、コントローラ）、1/60秒固定の更新、メニュー、文章パネル |
| `js/audio.js` | 効果音とBGMの合成、音量つまみの値の保存。音を作る関数は音声コンテキストを引数に取るので、画面なしで書き出して測れる |
| `test/bot.js` | 画面なしの確認（`node test/bot.js`）。数値の計測、補助の動作、自動操作でのゴール到達 |
| `test/audio.js` | 曲と効果音を画面なしで書き出し、平均とピークの大きさ、80Hz 以下の割合を出す |
| `test/*.js`（ほか） | Chromium の自動操作での確認。`stuck.js` は、指を離した後に入力が残らないことの検査 |

ステージと対象は `js/sim.js` の `buildLevel()` に書く。調べる対象は `put('term' / 'switch' / 'heal', 列, 行, {…})` の1行で置ける。

## 手触りの数値（`js/sim.js` の `C`）

1単位＝240行の画面の1ピクセル、1ステップ＝1/60秒。

| 項目 | 値 |
|---|---|
| 歩き | 1.5 / ステップ（加速なし） |
| ダッシュ | 3.5 / ステップ、1回 30 ステップ |
| ジャンプ | 初速 5.0、重力 0.25、落下の上限 5.75（高さ約3タイル、滞空38ステップ） |
| 距離 | 通常ジャンプ 約3.7タイル、ダッシュジャンプ 約8.5タイル、通常ジャンプ＋エアダッシュ 約9.3タイル |
| 壁蹴り | 初速 5.0、壁から離れる強制移動 7 ステップ |
| 先行入力 | ジャンプ 6、攻撃 10、ダッシュ 8 ステップ。足場を離れてから 4 ステップはジャンプ可 |
| ダッシュジャンプの猶予 | 14 ステップ |
| エアダッシュ | 18 ステップ |
| 三段斬り | 15 / 17 / 28 ステップ。次の段へは 7 / 8 ステップ目から |
| 溜め | 45 ステップ |
| ヒットストップ | 通常 3、三段目 6、溜め斬り 8 ステップ |

値は、参考にした16ビット時代の作品のおおよその数値から始めたもので、フレーム単位で一致させたものではない。原作にない補助は、連続ダッシュ、壁蹴りのダッシュ維持、ダッシュジャンプの長い猶予、エアダッシュ後の速度の持ち越し。ダッシュ中に姿勢が低くならない点（狭い通路をくぐれない）も原作と違う。

## 確認した範囲

- `test/bot.js`: 自動操作で、制御盤を動かして、ミスなしでゴールに到達。
- Chromium の自動操作: PC（1280×720）のキーとマウス、スマホ相当（844×390、568×320、縦持ち 390×844）のタッチ。
- 作者が手で遊んだ確認: スマホのタッチ、DualShock 4、キーボード＋マウス。
- **していない**: 音の聞こえ方の評価、iOS での確認、フレームレートの計測。

## 経過（操作まわりで決めたこと）

- キーボードだけの操作（J / K / L など）はやり辛い、という評価だった。右手をマウスに分けて解消した。
- マウス右に「クリックでジャンプ、長押しでダッシュ」を兼ねさせる案は、試して取り下げた（ジャンプが離した時点になり、ダッシュの出も遅れる）。マウス右はジャンプ、ダッシュは方向キーの2度押し、に落ち着いた。
- タッチの DASH から JUMP へ指を滑らせる操作は難しかった。DASH を1回押すと最後まで走る形にして、「DASH を押してから JUMP」で出るようにした。
- タッチのボタンは、大きさを上げ、当たりを「一番近いボタン」にして、ボタンの間の無反応をなくした。
